## 工具环境

- OpenSCAD 2021.01 在 `F:\Program Files\OpenSCAD\openscad.exe`（不在 PATH）
- **OpenSCAD 在中文路径下无法渲染** → 工作副本放 `D:\cad\`，改完同步回 `cad\`
- 命令行用数字选择器 `-D p=N`，别用 `-D part="x"`（PowerShell 吞引号）
- **写带中文的 .ps1 必须存成 UTF-8 with BOM**：Windows PowerShell 5.1 没有 BOM 就按 ANSI 读，中文全变乱码并报语法错。补救 `(Get-Content -Raw -Encoding UTF8 $p) | Out-File $p -Encoding utf8`。.scad 无所谓（OpenSCAD 认无 BOM 的 UTF-8）
- **PowerShell 的 `[ordered]@{}` 用整数下标取到的是"第几个"，不是键**。`$h[1]` 拿的是第 2 条。要按键取值就 `GetEnumerator()` 遍历——这个 off-by-one 让自检结果和期望值整体错了一位，差点当成真失败去改模型
- 嘉立创EDA 桥接已跑通，见 `easyeda-api` skill 与 [[easyeda-bridge-setup]]

## 锁定决策

- **语音是核心**：ESP32-S3-DevKitC-1 **N16R8** + ESP-SR，仅 3 条命令（起杆/落杆/复位）。**无喇叭/无TTS/无录音回放**
- **无爆闪灯、无闸杆灯带**；指示灯方案 = **在模块自带灯正上方开观察孔**（底座对 TP4056 充电灯，遥控器对 C3 板载蓝灯）
- **防砸 = 行程超时反转**（落杆超 1.15×T 反转、超 1.5×T 进 FAULT）。⚠️ 曾定"堵转电流检测"，**已推翻**——成品 DRV8833 模块不引出 `AISEN`，电机电流不经过 `GND` 脚，电阻串 GND 只能读到几 mA 静态电流。代价：响应从毫秒级变**秒级（0.2~1.6s）**、压紧力约 1.3N
- 玩家 6~10 岁
- **尺寸**：底座 **183×73×25**，承载底板 **120×65**（换算 `BASE_L=板长+63`、`BASE_W=板宽+8`）；闸体 46×46×62（`HS_X_ABS=51.5`，**绕 Z 转 +90°**）；闸杆 300×5×8 **沿 +Y 伸出**（v3.3 改：原来沿 +X，整机拉到 483mm 且不像道闸——真道闸是机箱在路边、杆子横跨路面）；**转轴离地 42、杆顶 46**（用户小车最矮 50，必须低于它）；起杆 90°；底座 2 键；Type-C + 总开关在**前端面**；遥控器 60×30×20 三键
- **转毂拆成 `hub`（主体，一整件）+ `cam`（凸轮盘）** —— 拆件与电机固定无关，是壁孔 φ8.5 卡住了 φ18.6 凸轮和 36×14 臂。拆点选凸轮而非臂：凸轮不传扭矩不受弯，主体保持整体承力
- **电机只靠矩形隧道夹紧**，不做 M1.6 支架板（端面 M1.6 孔留作日后加固）

## CAD v3.0（2026-08-14 解冻，12 项改完）

**12 个零件**：base_tray / base_top / house_l / house_r / hub / **cam(新)** / **btn_cap ×2(新)** / bar_a / bar_b / rc_bottom / rc_top / **rc_btn_cap ×3(新)**。全部 `Volumes=2 / Simple=yes`，`cad/run_check.ps1` **52 条用例全过**（含 24 条阳性对照，跑满一轮约 25 分钟）。

⚠ **导出表要和零件表一起改**：`rc_btn_cap`（`p=14`）建好之后一直没进 `export_stl.ps1` 的 map，**采购清单里有这个件、stl/ 目录里却没有文件**，谁都没发现。加零件的动作是"改 dispatch + 改导出 map + 跑自检"三件，少一件就静默漏。

🔴 **计划外抓到一条硬伤：闸体原来正压在起杆按键上。** PCB 定稿把按键放在 (0,+20)(+20,+20)，闸体占 x=2…48，x=20 那颗整个被盖住。**`HS_X_ABS` 25 → 55**（占 32…78）。连带上盖走线孔挪到 (55,−16.5)，在电池正上方，飞线贴电池顶面往 −X 走。

**转毂拆件后的固定链**（三者缺一不可）：角度靠 `cam` 的 **D 形孔配轴颈键面**定死（不用装配时对相位）；轴向靠几何夹（往外拔→凸轮撞 φ12 轴承凸台，往里推→夹杆臂撞外壁）；**顶丝只锁凸轮**，长在凸起背面（永远扫 −X/−Z 空象限），**闸体前面板开 φ3 进入孔**从外面拧——顶丝是径向的，从 y=0 分模面伸手够不着。⚠ 这颗顶丝是转毂唯一轴向固定，必须点螺纹胶。

**按键帽**：开关顶杆 17.6 / 盖面 25，差 7.4。帽 = 锥形下柄 + φ12 法兰(卡在背面 φ12.5 沉孔里) + φ8.5 柄露出 5mm。上盖背面加 **φ14×2.5 导向凸台**把沉孔从 1.5 加深到 **4.0**，导向跨距 4.5mm。**必须扣上盖前从背面放进去**。
⚠ **法兰厚 3.0 是算出来的，不是随手取的**：可压距离 = 沉孔深 4.0 − 法兰厚，必须大于 0.2(预留浮动，免得静止时预压开关) + 0.25(开关行程) = 0.45。取 3.5 只剩 0.05mm 余量，**打印公差 ±0.15 就能让法兰先坐死在沉孔底、开关根本压不到**。这类"两个尺寸之差决定功能"的地方，光看单个数字看不出问题。

## 遥控器（2026-08-15 起做，流程与主机一致）

**用户拍板三条**：❌ 无状态灯（原方案的"板载 WS2812/蓝灯"取消，顺带了结了两份文档打架）、❌ 无电量检测（100k/100k 分压静态 18.5µA，而深睡指标 <20µA，电池只有 250mAh）、✅ **外壳尺寸可动，优先装得下**。

**与主机唯一的流程差异**：主机的底座能随便放大所以"结构让路给 PCB"；遥控器 60×30×20 是**手持尺寸**，所以"塞不塞得下"必须**提前算**，不能等画完 PCB。算下来原尺寸装不下：高度差 2mm（电池 7 + 板 1.6 + C3 叠高 6.7 要 16 净高）、平面占用率 **71%**（正是主机布不通的那个数）→ 目标 **68×32×22**，最终仍以 PCB 定稿反推。

**原理图已建并校验通过**（工程 `道闸玩具遥控器` uuid `ea4e1a7afdae48fc87c730f80a6c9114`）。8 条网络：VBAT / VBAT_N / VSYS / V5 / GND / BTN_UP / BTN_DN / BTN_RST。

- 🔴 **GPIO2 是 C3 的 strapping 脚**，上电必须为高，而按键是拉低的 —— 按着键开机可能起不来。三个键最终落 **GPIO4/3/1**（U1 脚 13/12/10），全在深睡唤醒要求的 GPIO0~5 内。原计划的 GPIO5 在符号左侧，走线会与电源交叉，所以换掉
- 🔴 **拨动开关必须串在电池与 C3 的 5V 脚之间**。C3 板上 Type-C 的 5V 直通 5V 脚，开关放别处的话，插 USB 烧录时 5V 会顺着 5V 脚倒灌回 TP4056 的 OUT+（OUT+ 与 B+ 直连，保护只切负极）= 拿 5V 怼电池。开关串中间 = 关掉就物理断开。**规矩：烧录前先关开关**
- **电池引线用 1×2 排针封装当焊盘**（不装排针）。**不能用 KF128 端子**：高 9.5mm，而板面以上只有 6.9mm
- **U1 选直插版**（`_TH`，库里还有个贴片版）。直插好焊但叠高多 2.5mm；想省高度就换贴片版，代价是半孔手焊

**两条 EDA API 退化（这次新发现）**：
- **网络标识（GND/5V 符号）放不进去**：`sch_PrimitiveComponent.create` 放 netflag 类型必定卡 30 秒超时，EDA 大概率弹了命名框。**绕法是重排版面让所有网络都能用普通导线连通且零交叉**，不依赖标识
- `sch_Net.getAllNetsName()` 也返回空（不只是导线的 `getState_Net()`）。网表只能坐标几何重建
- 桥有 **30 秒**上限：一次调用里塞十几个 API（尤其 `lib_Device.search`）会超时。**搜索结果要缓存，或直接用 `{libraryType:"2", libraryUuid, uuid}` 构造引用跳过搜索**
- `lib_Footprint.get` / `.copy` 对系统库封装**都抛不透明错**（`[object Object]`）→ 封装几何只能等落到 PCB 里再读

### 遥控器结构（v3.1，PCB 定稿后反推）

**PCB 57 × 33**（x ±28.5、y −18…+15），**外壳 63 × 40 × 26**。三个方向都是被锁死算出来的：

- **长度双向锁死**：−X 端拨柄尖在 x=−32.5，外壁面必须落在 −31.5 才露得出来；+X 端 USB 插头壳长只有 6.5mm。**内腔哪边都不能加长**，想腾地方只能加宽
- **锁紧螺柱：四个板角一个都不能用**（分别切到 U2 的 6 脚焊盘、U1 下排焊盘、擦过 SW3 焊盘 0.45mm），而且 **−Y 边右半段被 U1 那排焊盘永久占死**（y=−13.12, x 7.11…24.89）。解法是板往 −Y 加宽 3mm 做**纯安装边**，四个缺口开在扫描验证过的空窗里
- **高度 26 不是 24**：24 时按键帽的 φ11 导向凸台底面在 19，而 U1 叠高顶面 20.4，**凸台撞模块**。凸台位置由 PCB 的按键坐标定死，挪不了，只能加高腔。**这条是自检 t=64 抓到的，不是算出来的**
- **两套坐标差 `RC_PCB_DY = 1.5`**：PCB 用自己的原点，外壳是对称 rbox。对准板上器件的特征一律写 PCB 坐标再加偏移
- **板四角倒 R2**（`RC_PCB_CR = 2`，CAD 与 EDA 已同步）：外壳是 R3.4 圆角，板子直角时板角到腔壁只剩 0.34mm，倒 R2 后升到 1.0mm（再倒大没用，这时卡的是直边净距）。**主机那块板不用倒**——它的角落是 45°×7 倒角，本来就让开了

**❌ 不开 U1 的烧录口**：充电器插错到 C3 那口时，5V 经 5V 脚 → 拨动开关 → TP4056 的 OUT+，而 OUT+ 与 B+ 直连（保护只切负极）= 直接怼电池，靠 DW01 兜底。开发板烧不了，但那是靠保护救命。串肖特基要付 0.3V 压降。**改成拆壳拔模块烧录**（排母就是为此装的）。

## 采购卡点（买错就装不上）

- **排母只买低背 5.0mm**，常见的 8.5mm 装不下
- **限位开关必须带簧片杠杆**（ZIPPY DF-P1S-1E-M-Z），无杠杆直动式行程 0.3mm 会被 3.3mm 凸轮升程压毁
- **轻触开关 6×6×12，动作力 100~160gf**，别买 300gf
- **拨动开关 SK12D07VG7**（卧式侧拨），不是立式的 SS12D00G3
- **MT3608 买 37×17 那款**（无 USB 座，实物尺寸图为准），SX1308 高 12mm 装不下

## 教训（都是真金白银换的）

1. **`Volumes=2 / Simple=yes` 只证明单件几何合法，完全不证明能装配。** v2.2 九件全过，用户仍发现 4 处装不上的硬伤。v2.3 起改用**布尔交集自检** `cad\check.scad`，并且**必须带阳性对照**（故意摆错必须非空），否则检测失效了都不知道。**但它测的是终态，测不出装配路径** —— 转毂穿不过壁孔就是自检抓不到的。
2. **模块叠高要一层层数。** DevKit = 排母 + **公排针塑料隔片 2.5** + 板 1.57 + 模组 3.1，四层。漏掉隔片那层就是 2.5mm，直接决定方案成不成立。
3. **转动件的限位不能靠"把挡块摆到那个角度"。** 挡块要待在转动件的**扫掠包络之外**，包络由"侧面到转轴的距离"决定而非角度。用**扫掠差集**生成位置，且**相邻角度实例必须取 `hull()` 填缝**——只做并集会在尖端半径漏出细缝，变成提前挡路的毛刺。
4. **几何"看起来对"不等于对。** D 形孔曾被写成 圆 **并** 方槽（应为 圆 **交** 半空间），渲染图上看不出来，实际轴插进去空转。这类问题只能用阳性对照钉死。

5. 🔴 **CAD 里的元件/板子模型必须回源头验一次，而且要警惕"偏乐观"的错误。** CAD 把承载底板的 −X 两角建成 **5×5 方形缺口**，而 EDA 里的实际板框是 **45° 倒角**。方缺口挖掉的料更多 → 自检一直报"没问题"，**错在偏乐观的方向，比报错更危险**。按真实倒角算，角螺柱中心到斜边只有 2.47mm 而螺柱半径 3.0，**板子啃进螺柱 0.53mm、根本装不进去**。倒角加大到 7 才让开 0.89mm。和 DevKit 封装行距那次是同一个根因：**文档/CAD 里的数没回源头核过**。
6. 🔴 **带孔的柱子不能"整体 union"上去 —— 孔会被它插进去的那块料重新填实。** 托盘的承载底板支撑柱就是这么写的，底孔在 2mm 厚地板那一段被填死，实际底孔只从 z=2 才开始，M2 自攻要在实心料里硬攻 1.4mm。README 坑 #2 当初只在闸体上做对了，托盘漏了。**正确顺序：先并实心特征，最后统一开孔。** 自检 `t=24` 抓到的。
6.5 🔴 **"接口对得准"和"插头插得进"是两回事，别用前者证明后者。** 前端面 Type-C 开口 10×5 一直被认为没问题——它确实**对准了座子**，也确实**比金属壳(8.34×2.56)大**。但 Type-C 完全插入时**塑料头前端面基本贴住座口**，所以从外壁面到座口那 3.27mm 死区**得由塑料头自己钻过去**；塑料头实测 11×6.5，过不去 10×5，插头顶在外壁上，金属壳只进一半，接触不上。文档里那句"插头长 6.5mm，穿 2mm 壁 + 1.7mm 间隙仍插得到底"**算术就不成立**：6.5 − 3.7 = 2.8mm 咬合而已。**凡"插拔类接口"，要建的模型是连塑料头在内的整个插头，不是那根插进去的芯子。**

6.6 🔴 **孔位完全对齐 ≠ 螺丝拧得下去 —— 要查的是螺丝头投影范围内有什么。** 承载底板四个安装孔与托盘支撑柱零偏差、孔径 φ2.2 配 M2 也没错，文档里"安装孔净空冲突 0"也是真的。但 M2 盘头 φ3.5~4.0，**(−82,27) 那颗螺丝头底下同时压着 `VBAT_SW` 走线(铜边距孔心 1.5mm)和 GND 覆铜，中间只隔一层阻焊** = 拧紧就可能把电池正极对地短路。**孔位表永远查不出这个**，因为问题不在孔里、在孔周围一圈。判据：**孔心到任何非 GND 铜箔 ≥ 2.5mm**（头半径 2.0 + 0.5 公差）。

6.7 **"选型自由度"表格换了基准尺寸就得回头重算，判据留着、坐标作废。** 拨动开关拨柄高度 H 的选型表是按老底座（外壁面 −75）列的，底座放大到 183×73 后外壁面变成 −91.5，表没重算，H=7 一路用到 PCB 定稿 —— 结果拨柄只露 **0.51mm**，连那张表自己写的"露 1mm 才拨得动"都不满足。**判据是对的，错的是坐标。**

7. **跨零件的约束会在两边都改完之后失配，而布尔自检抓不到。** "按键 x<2，因为闸体占 2…48"这条注释写在按键参数旁边，后来按键位置改由 PCB 定、闸体也没人回头看，结果闸体正压在按键上。**求交永远是空的——两者根本不在同一个零件里。** 约束要写在会被改动的那一方，而且换事实源（这里是按键位置从"结构挑"变成"PCB 定"）时必须回头扫一遍引用它的注释。
8. **自检用例里不许留共面接触。** 面贴面求交，CGAL 给的是零体积薄片，导出 STL 有几百个三角形，按文件大小判"空/非空"会误判成非空。v3.0 第一轮 5 条假失败全是这个（交集 bbox 形如 `z[22.00..22.00]`）。凡"应该刚好贴上"的地方一律错开 0.01~0.05 再求交。**排查手段：看交集的包围盒，某一轴塌成一个数就是共面。**
9. **阳性对照本身也要验算。** 遥控器那批用了个"12mm 高的开关必须顶到上盖"的对照，可板面 8.7 + 12 = 20.7 根本够不到 23 的盖背面 —— **这个对照永远会过，等于没设**。改 16mm 才成立。**一个永远通过的对照比没有对照更危险**，它给人"我有对照"的错觉。
10. **测试模型必须和真件同形**。验"板装不装得进腔里"时拿了一块**没有螺柱缺口**的方板，撞的是我自己画错的模型，不是设计缺陷。同一条还漏了 Z 向：只在 XY 缩 0.05，交集出来是零厚度薄片（那是板本该坐在承托肩上的贴合面）——**缩要三个方向一起缩**。
11. **阳性对照要覆盖"东西根本不存在"。** 验开关底孔"没打穿外壁 / 是通的"那两条，**整块安装台不存在时照样过**——没有料求交当然是空的。补了"孔四周有料"的用例，而且**两块安装台分开验**：合成一条只要有一块在就非空了。
12. **探针直径要配孔的类型。** φ2.0 探 M2 过孔(φ2.4)合适，探自攻底孔(φ1.7)永远探不通——那是探针选错，不是零件有毛病。
13. **静态求交测不出装配路径，但可以换个写法测。** `t=40`：把"必须穿过 φ8.5 壁孔的那一段"减掉壁孔通道，剩下的必须为空；`t=41` 阳性对照把凸轮装回去（=一整件）必须非空。这条直接钉死了"转毂穿不过壁孔"那类问题。

**另加一条方法论**（2026-08-12 用户提出，已成为项目原则）：**先定元件尺寸，再动 3D。** v2.2~v2.6 连续四轮修的硬伤根因是同一类——拿没核实的元件尺寸建模。同理，**卖家详情页的"行程"是典型值，官方规格书的 `PT Max` 才是设计依据**（这条差点让一批限位开关全部失效）。

## 布线要点（2026-08-14）

**先算后画**：两个校验脚本在下笔前算间距（`clearance.js`：每段对所有异网焊盘+同层异网走线，阈值 0.2mm）、画完用回读铜箔验连通（`connect.js`）。一共拦下 30+ 处问题，其中三处是模型缺陷：**U1 的 24 个未用引脚也要避让**（两排 2.54 满排，穿越只有 1.02mm 的缝）、**贴片焊盘只在顶层不该双面挡**、**安装孔是独立焊盘 getAllPins 取不到**。

**0 过孔**：`pcb_PrimitiveVia.create` 建的过孔位置/网络/类型/尺寸全对，EDA 仍报"与同网络其它对象断开"，不认它导通（原因未明）。绕法是**所有换层都发生在 THT 焊盘上**。为此把 VBAT_PROT 改走底层、并**对调 J2 的两个限位端子**（限位开关是飞线接的，端子分配自由）——⚠ **J2.2=落杆限位、J2.3=起杆限位**，装配按此接。

**自动布线不可用**：`autoRouting()` 一律返回全部失败 duration:0；界面点按钮报"请先绘制板框"，但板框是好的（zoomToBoardOutline 返回 true、3D 能生成、6 段线闭合）。判断是该功能受限。

**覆铜只能手工画**（`IPCB_Polygon` 无公开构造方法，Polyline/Region/Pour 都要它）。⚠ **画完必须 `rebuildCopperRegion()`**，否则铜与走线间距为 0 等于全短路；⚠ **两面都要铺**，底层铜够不着顶层贴片的 GND 焊盘。

## 固件（2026-08-28 开工，骨架完成）

`firmware/` 下两个独立 ESP-IDF 工程，共用 `common/gate_proto.h`（12 字节 `gate_pkt_t`，CRC16-CCITT，已用标准向量 0x29B1 验过）。

- `gate/`（S3）：`motion.c` 状态机 + `motor.c`(LEDC 20kHz/11bit) + `endstop.c` + `input.c` + `buzzer.c` + `comms.c`
- `remote/`（C3）：无常驻任务，唤醒→发一条→深睡
- **M1~M4 逻辑齐，M5 语音是桩**（`sr.c`，接口已钉死，实现后 main.c 不用动）

**三条上电前必须确认的**（都写进 `firmware/README.md`）：`MOTOR_INVERT` 现在是猜的 0、限位 NC/NO 极性、M1 必须 USB 供电。

**偏离方案文档一处（有意）**：§7.1 说"首次 HOMING 标定 T"，但 HOMING 是从未知角度走残段，量到的 T 偏小 → 防砸阈值偏小 → 正常落杆被误判成夹到东西。改成只采纳"限位到限位"的完整行程 + EMA。

**代码里两个坑**：① 限位模块必须叫 `endstop.h` 不能叫 `limits.h` —— `main/` 在 include path 上会盖掉标准库 `<limits.h>`；② 底座单键要**等松手才动作**，按下即动作的话双键长按复位必然先误触发一次抬杆或落杆。

**上电自检**：两个限位同时读到"到位"是物理不可能（0° 和 90° 不能并存），只可能接线错或 NC 接成 NO → 直接 FAULT，不转电机去试。

**顺手修掉两处事实源打架**（固件正好依赖）：① 方案 §4.2 正文写"取 GPIO3/4/5"，而表格和实际是 **4/3/1**（GPIO5 在符号左侧要绕线，换掉了）—— 正文已标作废；② 网表基准 §3.3 的 N16/N17 还写着对调前的 J2.2/J2.3，已按 PCB 定稿改正并补说明。

**工具链**：装的是 **ESP-IDF v6.1-beta1**（我建议 v5.4，用户用 eim 装成了 v6.1-beta1）。框架 `D:\esp\v6.1-beta1\esp-idf`、工具 `D:\Espressif\tools`、**激活脚本 `C:\Espressif\tools\Microsoft.v6.1-beta1.PowerShell_profile.ps1`**（不是 export.ps1）。
