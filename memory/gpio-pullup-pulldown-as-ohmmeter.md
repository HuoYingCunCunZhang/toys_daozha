**判断"某个 GPIO 是不是被短路拉死了"，不要用万用表断电量通断——用芯片自己的内部上拉/下拉轮流读一遍。**

对每个脚：开上拉→等几 ms→读；开下拉→等几 ms→读。

| PU | PD | 结论 |
|---|---|---|
| 1 | 0 | 脚是自由的，上拉拉得动 = 正常 |
| 0 | 0 | 45kΩ 上拉都拉不高 = **被低阻路径拉死在地** |
| 1 | 1 | 拉死在 VDD |

**而且必须带一个"板上什么都没接"的引脚当对照脚**（道闸遥控器用的是 GPIO5）。对照脚读到 `PU=1 PD=0`，才证明芯片和测法都是好的，那三条 `PU=0 PD=0` 的结论才立得住。

**Why:** 2026-09-13 查遥控器"三个键没按就全读 0"，用万用表断电量通断连着测错两轮：
① 不上电去量芯片引脚，**内部 ESD 钳位二极管会在蜂鸣档的开路电压下导通**，表会响，但那是测量假象不是短路；
② 进了下载模式再量电压，**ROM 不配上拉**，读到 0V 同样什么都证明不了，连"按住键"的阳性对照都失效（按不按都是 0V）。
前后两轮的读数互相矛盾（同一个点一次"通"一次"不通"），全是因为**每次只量疑似有病的点，没有健康样本作对比**。换成 PU/PD 读法，一屏就定案。

**How to apply:** 写个不深睡、不开射频、每 0.5s 刷一屏的诊断固件，把待查脚和对照脚放一起打印。附带好处：不深睡就不会每 11.4s 掉一次串口。诊断固件**要进仓库**（道闸项目在 `firmware/rcdiag/`）—— 放在 `D:w\` 里会被 README 那条 `robocopy ... /MIR` 当多余文件删掉，而且修完硬件还要再用一次。⚠ **打印用纯 ASCII 标签**——中文经 USB-JTAG 读回来会变 `??`，白白干扰判读。相关：[[c3-usb-jtag-reset]]、[[verify-selectively]]
