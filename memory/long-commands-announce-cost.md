跑耗时数分钟的命令前，**先用一句话说清"这步大概多久、为什么慢"**，或者放后台跑。

2026-08-28 固件首次编译：ESP-IDF 冷编译 1087 个目标文件，一轮几分钟，我连跑了 set-target + build 且没作声。用户中途打断问「你在干什么为什么还没有编译完成」——**而主机那次其实已经编完了**，用户没看到而已。

**Why**：工具输出只给我看，不可靠地显示给用户。长命令 + 不出声 = 用户面前是纯静默，跟卡死没有区别。

**How to apply**：
- 本项目已知的长命令：`idf.py build`（冷编译几分钟）、`cad/run_check.ps1`（52 条用例约 25 分钟，见 [[daozha-toy-scope]]）
- 开跑前一句：「冷编译 1087 个文件，几分钟」
- 更长的（十几分钟以上）直接 `run_in_background`，别占着对话
- 一步做完就报一次结果，别攒着几步一起报 —— 用户判断"是不是卡住了"靠的是这个

配套：[[verify-selectively]]（别烧 token 跑全流程）。
